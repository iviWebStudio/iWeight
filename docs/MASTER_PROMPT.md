2. GPT — ОБЯЗАТЕЛЬНЫЙ ИНТЕЛЛЕКТУАЛЬНЫЙ ДВИЖОК ПРИЛОЖЕНИЯ

Внутри конечного приложения должен работать именно GPT через официальный OpenAI API.

Не заменяй GPT моделью Anthropic, Gemini, локальной LLM или другим поставщиком без моего явного разрешения.

Используй актуальную официальную документацию OpenAI на момент разработки. Предпочтительно используй Responses API, если актуальная документация и выбранные возможности подтверждают его пригодность для проекта.

Требования:

- Вызовы модели выполняются сервером.
- Модель задаётся через переменную окружения OPENAI_MODEL.
- API-ключ задаётся через OPENAI_API_KEY.
- Не зашивай название модели в код во множестве мест.
- Не используй устаревшие методы, если для задачи есть актуальный поддерживаемый вариант.
- Используй поддерживаемые механизмы вызова функций и структурированных ответов.
- Проверяй аргументы каждого инструмента на сервере.
- Ограничивай число итераций вызова инструментов.
- Обрабатывай тайм-ауты, ограничения частоты запросов, ошибки API и недоступность модели.
- Веди учёт использования токенов и расходов.
- Предусмотри возможность смены модели через конфигурацию без переписывания бизнес-логики.
- Не отправляй в OpenAI больше персональных данных, чем необходимо для конкретного запроса.
- Не передавай API-ключи и секреты в браузер, Android-приложение, логи или клиентские сборки.

Если выбранная модель или функция недоступна в аккаунте, не подменяй её молча. Проверь официальную документацию, предложи совместимый вариант исообщи о необходимом выборе.

Разделение инструментов разработки и модели продукта

Если разработка выполняется в Claude Code, он может использовать собственные возможности программирования. Это не меняет обязательного требования: конечное приложение должно обращаться к GPT через OpenAI API.

Если работаешь в GPT/Codex, используй доступные средства разработки OpenAI.

Не путай модель, которая пишет код, с моделью, которая работает внутри готового приложения.

4. ПАМЯТЬ GPT-АГЕНТА В КОНЕЧНОМ ПРИЛОЖЕНИИ

Разработай отдельную память пользовательского агента. Не смешивай её с памятью команды разработки.

Предусмотри следующие уровни:

1. Постоянные правила агента: версия системной инструкции и политики поведения.
2. Профиль пользователя: настройки, единицы измерения, часовой пояс, выбранный формат отчёта.
3. Структурированная память: цели, подтверждённые предпочтения и устойчивые пользовательские правила.
4. История измерений: авторитетные записи в базе данных.
5. История диалогов: сообщения, необходимые для продолжения беседы.
6. Краткое резюме контекста: обновляемое описание существенных фактов и последних действий.
7. Настройки агента: версия инструкций, разрешённые инструменты, лимиты и конфигурация модели.

История веса и цели всегда берутся из базы данных, а не из свободного текстового резюме.

Резюме памяти не должно иметь возможность незаметно изменить измерение, цель или другой авторитетный факт.

При каждом новом запросе формируй контекст только из данных текущего авторизованного пользователя.

Не передавай GPT историю другого пользователя.

Не сохраняй чувствительные сведения в долговременную память без необходимости и предусмотренного правилами согласия.

Добавь возможность просматривать, исправлять и удалять пользовательскую память, а также предусмотренный процесс удаления аккаунта и связанных данных.

Реализуй отдельный модуль вычислений.

Он должен поддерживать:

- изменение от начального веса;
- число прошедших календарных дней;
- среднюю скорость в граммах в день;
- среднюю скорость за неделю;
- остаток до цели;

- достижение цели;
- превышение цели;
- отсутствие устойчивого тренда;
- ошибочную дату;
- некорректное значение веса;
- дубликат записи;
- несколько записей за один день;
- разные часовые пояса.

Проверь формулы независимыми тестовыми примерами. Не полагайся только на собственное текстовое объяснение результата.

Обязательные endpoint-ы:

- "GET /v1/me"
- "PATCH /v1/me"
- "GET /v1/weights"
- "POST /v1/weights"
- "PATCH /v1/weights/:id"
- "DELETE /v1/weights/:id"
- "GET /v1/analytics/summary"
- "GET /v1/analytics/history"
- "POST /v1/goals"
- "POST /v1/chat"

При необходимости добавляй endpoint-ы для пользовательской памяти и настроек агента.

Все запросы должны проверять аутентификацию и права доступа на сервере.

Не доверяй "user_id", переданному клиентом. Получай идентификатор из проверенной сессии или токена.

Обязательно реализуй:

- Row Level Security;
- проверку владельца записи;
- валидацию входных данных;
- безопасную обработку ошибок;
- защиту от повторных запросов;
- ограничения частоты запросов;
- лимиты размера запросов;
- корректную обработку параллельных операций;
- серверное управление секретами;
- безопасные логи без ненужных персональных данных.

Не используй административный ключ Supabase в браузере или Android-клиенте.

Секреты должны храниться в переменных окружения или менеджере секретов. Создай ".env.example" без реальных секретов и добавь ".env" в ".gitignore".

10. ЭТАП 5 — GPT-АГЕНТ

Создай рабочий агент, а не демонстрационный чат.

Агент должен:

- понимать естественный язык;
- распознавать ввод нового веса;
- определять намерение пользователя;
- задавать уточняющий вопрос при неоднозначной дате или значении;
- получать историю через серверные инструменты;
- получать статистику через расчётное ядро;
- сохранять измерение только через разрешённый инструмент;
- изменять цель только по явному запросу;
- объяснять изменение веса;
- формировать отчёты по установленному формату;
- учитывать пользовательские предпочтения;
- сохранять разрешённую память;
- продолжать работу после перезапуска приложения;
- обрабатывать ошибки API и повторные запросы.

Минимальный набор инструментов:

- "get_user_profile";
- "get_weight_history";
- "calculate_weight_analytics";
- "add_weight_entry";
- "update_weight_entry";
- "delete_weight_entry";
- "manage_goal";
- "get_agent_memory";
- "update_agent_memory";
- "generate_report".

Реализуй каждый инструмент на сервере. Проверяй аргументы, пользователя, права и результат операции.

Не позволяй модели напрямую выполнять произвольный SQL.

Не позволяй ей считать, что запись сохранена, пока сервер не подтвердил успешную операцию.

Для изменяющих данные операций реализуй необходимые проверки и подтверждение намерения. Удаление истории, удаление аккаунта и необратимые действия должны иметь особенно строгие правила.

Создай системную инструкцию GPT в отдельном файле и версионируй её. Отдели неизменяемые системные правила от настроек пользователя.

Используй структурированные ответы, когда это помогает гарантировать правильный формат данных.

Создай набор тестовых диалогов для проверки поведения агента. Проверяй не только качество текста, но и то, какие инструменты были вызваны и какие данные реально изменились.
