## Принципы
- Интеграционные тесты API идут против реальной БД `weight_ai_test` с теми же миграциями и RLS,
  что пойдут в Supabase (через шим, ADR-006). Каждый тест создаёт своих пользователей и удаляет их.
- Изоляция пользователей проверяется на трёх уровнях: HTTP (404 на чужие id, отказ на подмену
  `user_id`), сырой SQL под ролью пользователя (RLS), роль API без `SET ROLE` (нет доступа вообще).
- Агент тестируется со скриптовым двойником модели (`ScriptedModel`): проверяются вызванные
  инструменты, что вернулось модели и фактические изменения в БД. Сбой проверки внутри шага модели
  валит тест (`afterEach`), неиспользованные шаги — тоже.
- E2E: настоящий браузер, настоящий API и БД; модель — детерминированный двойник
  (`apps/api/src/test/e2e-server.ts`, только для тестов).
