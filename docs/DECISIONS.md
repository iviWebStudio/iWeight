# DECISIONS (ADR-журнал)

## ADR-001 TypeScript 5.9.3, а не 7.x (2026-10-23)
`latest` в npm — TS 7 (нативный порт). Совместимость Next 16 / Expo 58 / Vitest 5 с ним не
проверена → зафиксирован 5.9.3. Пересмотреть отдельной задачей.

## ADR-002 Вес — целые граммы (2026-10-23)
Без плавающей точки в БД и расчётах. kg/lb — только на границах (`core/units.ts`).

## ADR-003 Календарная дата в поясе пользователя (2026-10-23)
`measured_on date` = дата в часовом поясе профиля; `measured_at timestamptz` — опционально.
Вся арифметика дней — по epoch-дням UTC (DST не сдвигает дни).

## ADR-004 Несколько записей в день разрешены (2026-10-23)
Аналитика берёт одно значение на день — самое раннее по `measured_at` (записи без времени идут
после записей со временем). Дубликаты: идемпотентный повтор по `(user_id, client_entry_id)`;
уникальность `(user_id, measured_at)`; совпадение даты+веса без времени → API отвечает 409
`DUPLICATE_ENTRY`, если клиент не передал `allowDuplicate`.

## ADR-005 RLS применяется и в API (2026-10-23)
API подключается к Postgres отдельной ролью без собственных прав на таблицы и в каждой транзакции
делает `SET LOCAL ROLE authenticated` + `set_config('request.jwt.claims', …, true)`. Ошибка в коде
API не может обойти RLS. Локально роль `weight_api` получает `authenticated` с `INHERIT FALSE`
(fail-closed). На Supabase — пользователь пулера (transaction mode поддерживает `SET LOCAL`).
`user_id` клиента никогда не принимается — только `sub` проверенного JWT.

## ADR-006 Локальный Postgres без Docker + шим Supabase (2026-10-23)
В песочнице Docker-демон недоступен → `supabase start` невозможен. `db/local/00_supabase_shim.sql`
воспроизводит роли, `auth.users`, `auth.uid()`. Миграции в `supabase/migrations` — те же, что
пойдут в Supabase. На машине с Docker можно использовать `supabase start` вместо шима.

## ADR-007 Адаптер аутентификации (план, 2026-10-23)
`AUTH_PROVIDER=supabase` (по умолчанию): API проверяет JWT Supabase через JWKS
(`${SUPABASE_URL}/auth/v1/.well-known/jwks.json`, aud `authenticated`), клиенты логинятся
`@supabase/supabase-js`. `AUTH_PROVIDER=local`: только dev/CI — `/v1/auth/local/{signup,login}`,
scrypt-хэши в шим-таблице, HS256-токены той же формы; сервер отказывается стартовать с ним при
`NODE_ENV=production`.

## ADR-008 История целей (2026-10-23)
Смена цели = старая получает `replaced`, новая вставляется в той же транзакции. Одна активная
цель (частичный уникальный индекс).

## ADR-009 Подтверждение разрушительных действий через чат (2026-10-23)
`delete_weight_entry` без `confirmation_id` не удаляет, а создаёт `conversations.pending_action`
(тип, id записи, срок 10 мин) и возвращает `confirmation_required`. Исполнение — только с этим id
и только если после создания пришло новое сообщение пользователя. Удаление аккаунта через чат
недоступно вовсе (только UI с вводом подтверждения).

## ADR-010 Конфигурация агента (2026-10-23, реализовано)
Тексты системной инструкции версионируются в git (`apps/api/src/agent/prompts/vN.ts`);
`agent_config_versions` хранит активную версию, разрешённые инструменты, лимит итераций и снимок
промпта для аудита. Модель — `OPENAI_MODEL` (опционально `model_override` в строке конфига).
Нет активной строки — используется версия из кода; лимит шагов — минимум из строки и
`OPENAI_MAX_TOOL_ITERATIONS`.

## ADR-011 Автономное демо (2026-10-23)
`apps/demo` — один HTML-файл без сервера: настоящее `packages/core` (бандл esbuild, IIFE
`WeightCore`), данные в `localStorage`, чат — локальный сценарий, имитирующий вызовы инструментов
агента из ТЗ §10. Нужен, чтобы владелец видел продукт до готовности API/GPT. Это не замена web-клиенту
(шаг 6) и не источник логики: все расчёты — из ядра, агент в продукте — только GPT через OpenAI API.

## ADR-012 Вызовы модели вне транзакций БД (2026-10-23)
Ход чата: короткая транзакция подготовки → цикл модели, где каждый инструмент выполняется в своей
RLS-транзакции → короткая транзакция сохранения ответа и `agent_runs`. Долгий вызов OpenAI не держит
соединение пула и блокировки. Цена: если модель упала посреди хода, уже выполненные инструментами
изменения остаются: сервер их выполнил, но ответа с их описанием пользователь не получит (клиент
видит ошибку и может повторить запрос с тем же `clientMessageId`). Поэтому запись из чата идемпотентна (детерминированный `clientEntryId`), а удаление требует
подтверждения в отдельном сообщении.

## ADR-013 Инструменты возвращают готовые строки (2026-10-23)
Числа в результатах инструментов уже посчитаны ядром и отформатированы в единицах и на языке
пользователя (`80,6 кг`, `−0,4 кг/нед`; для en — `80.6 kg`), чтобы модель могла цитировать их как есть. Модель не делает арифметику и конвертацию (требование ТЗ §1).
`strict: false` у function tools: аргументы всё равно проверяются Zod на сервере, а схемы не
приходится подгонять под ограничения strict-режима.

## ADR-014 Суточный бюджет токенов (2026-10-23)
`CHAT_DAILY_TOKEN_BUDGET` на пользователя, сумма `agent_runs` с полуночи в его часовом поясе;
превышение → 429 `AI_BUDGET_EXCEEDED`, дневник продолжает работать. Стоимость в `agent_runs`
считается по `OPENAI_PRICE_*_PER_MTOK` (цены задаёт владелец, в коде их нет).

## ADR-015 Вход в web: адаптер Supabase / локальный (2026-10-23)
`apps/web/lib/auth.ts`: при заданных `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_ANON_KEY` —
Supabase Auth (`@supabase/supabase-js`), токен сессии уходит в API. Без них — локальные endpoint-ы API
(только dev/CI; API отказывается от них в production). Токен локального режима хранится в
`localStorage` — допустимо только для разработки.

## ADR-016 «Сейчас» записывается с моментом времени (2026-10-23)
Записи без времени по ADR-004 идут после записей со временем, поэтому вес, введённый «сейчас»
(онбординг, быстрый ввод, чат «сегодня 80,6» без времени), сохраняется с `measuredAt = now`. Иначе
вечерняя запись с временем становилась «утренней». Найдено e2e-тестом. Для прошлых дат без времени
`measuredAt` по-прежнему пуст.

## ADR-017 Деплой: Supabase + Vercel Hobby (2026-10-24)
Бесплатно и разворачивается без своих серверов. API — одна serverless-функция (`apps/api/api/index.mjs`
→ `src/vercel.ts`), Fastify-экземпляр кешируется в тёплом инстансе, пул pg ≤ 3, к БД — через
transaction pooler Supabase (поддерживает `SET LOCAL`, ADR-005). API подключается ролью `weight_api`
(миграция `20261024000001_api_role.sql`, пароль задаёт владелец). Токены Supabase: JWKS для
асимметричных ключей, `SUPABASE_JWT_SECRET` для старых HS256-проектов. Из этой среды нет сетевого
доступа к API Vercel, поэтому деплой — через git: Vercel собирает каждый push.
