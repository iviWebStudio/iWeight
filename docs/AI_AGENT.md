# AI_AGENT

Агент — GPT через официальный OpenAI API (Responses API, SDK `openai` 7.43.0), вызывается только
сервером. Модель — `OPENAI_MODEL` (или `model_override` активной строки `agent_config_versions`).
Без `OPENAI_API_KEY`/`OPENAI_MODEL` чат отвечает 503 `AI_NOT_CONFIGURED`, остальное API работает.

## Где что лежит
- `apps/api/src/agent/prompts/v1.ts` — системная инструкция v1 (неизменяемые правила). Новая
  редакция = новый файл и версия. Активной может стать строка `agent_config_versions` (оператор),
  иначе используется версия из кода. Версия пишется в каждый `agent_runs`.
- `agent/tools.ts` — 10 инструментов из ТЗ §10.
- `agent/runner.ts` — один ход диалога; `agent/model.ts` — обёртка OpenAI и маппинг ошибок.

## Ход диалога
1. Транзакция (RLS): идемпотентность по `clientMessageId`, диалог, сохранение сообщения
   пользователя, проверка суточного бюджета токенов, сборка контекста.
2. Цикл: модель → вызовы инструментов (каждый — отдельная RLS-транзакция) → модель. Не больше
   `max_tool_iterations` шагов; на лимите — финальный вызов с `tool_choice: none`, `limited: true`.
   Вызовы модели идут вне транзакций — медленная модель не держит соединение и блокировки.
3. Транзакция: ответ ассистента с `tool_events`, запись `agent_runs` (модель, версия, статус,
   токены, стоимость, инструменты, шаги, задержка). При ошибке OpenAI — запись `status=error`.
4. Если в диалоге > 30 сообщений вне резюме — модель обновляет `conversations.summary`
   (без весов, дат измерений и целей). В модель уходят резюме + последние 20 сообщений.

## Контекст (только текущий пользователь)
Системная инструкция + имя, «сегодня» и пояс, единицы, язык, формат отчёта, тон; память агента
(если не выключена); резюме диалога; ожидающее подтверждения удаление. Email и чужие данные не
передаются. Вес и цели в контекст не кладутся — агент читает их инструментами из БД.

## Инструменты
| Имя | Что делает | Пишет |
|---|---|---|
| `get_user_profile` | имя, пояс, сегодня, единицы, настройки | — |
| `get_weight_history` | записи с id, датой, местным временем, весом, флагом «утреннее» | — |
| `calculate_weight_analytics` | сводка ядра с готовыми строками в единицах пользователя | — |
| `add_weight_entry` | запись веса; результат — изменение к прошлому утру, среднее 7 дней | да |
| `update_weight_entry` | исправление записи (до/после) | да |
| `delete_weight_entry` | два шага, ADR-009 | да |
| `manage_goal` | поставить/снять цель; результат — прогноз | да |
| `get_agent_memory` | память | — |
| `update_agent_memory` | добавить/изменить/удалить; веса и цели не принимаются; уважает `memory_enabled` | да |
| `generate_report` | отчёт за неделю/месяц/период и сравнение с предыдущим | — |

Аргументы проверяются Zod; ошибки (валидация, «не найдено», чужая запись) возвращаются модели как
`{ ok: false, error }`, а не исключением. Все числа приходят готовыми строками (`"80.6 kg"`,
`"−0.4 kg"`) — модель ничего не считает и не конвертирует. Запись веса из чата получает
детерминированный `clientEntryId` (хэш сообщения и аргументов) — повтор вызова не создаёт дубль.

## Удаление (ADR-009)
Без `confirmation_id` инструмент только создаёт `conversations.pending_action` (10 минут) и
возвращает `confirmation_required`. Удаление выполняется, только если `confirmation_id` совпадает,
не истёк и пришёл в более позднем сообщении пользователя, чем создан. Удаление аккаунта и массовое
удаление через чат недоступны.

## Ошибки OpenAI
SDK сам повторяет 408/409/429/5xx и сетевые ошибки (2 ретрая с backoff), таймаут —
`OPENAI_TIMEOUT_MS`. Далее: таймаут/сеть/429/5xx → 503 `AI_UNAVAILABLE` (`details.reason`);
401/403 → 503 `AI_NOT_CONFIGURED`; 404 модели → 503 `AI_NOT_CONFIGURED`, `reason: model_unavailable`
— модель молча не подменяется.

## Тесты
`apps/api/src/test/chat.test.ts`: модель заменена скриптовым двойником (`ScriptedModel`). Проверяется,
какие инструменты вызваны, что вернулось модели и что реально изменилось в БД. Сбой проверки внутри
шага модели валит тест (иначе сервер превратил бы его в 503).
